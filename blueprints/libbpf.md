# Blueprint: libbpf/libbpf

> **Source**: [https://github.com/libbpf/libbpf](https://github.com/libbpf/libbpf)  
> **Domain / Category**: Kernel & Low-Level Systems  
> **Core Architectural Purpose**: `libbpf` acts as the definitive user-space C/C++ library for loading, verifying, and managing Extended Berkeley Packet Filter (eBPF) programs and maps into the Linux kernel. It bridges user-space ELF object files and kernel-space execution hooks by abstracting system calls (`bpf()`), handling BTF (BPF Type Format) relocation, and enabling portable BPF CO-RE (Compile Once – Run Everywhere) transformations.

---

## 1. Architectural Topology & Entry Points

### System Boundaries
- **Syscall Layer**: Directly invokes the Linux kernel `bpf()` system call (`sys_bpf`) via raw assembly/wrappers to create maps, load programs, and attach tracing or networking hooks.
- **ELF Parsing Layer**: Consumes ELF object files generated by LLVM/Clang, parsing section headers, symbol tables, and relocation entries.
- **Kernel Subsystem Interface**: Interfaces with `perf_event`, `netlink`, `xdp`, `cgroups`, and tracing infrastructure (kprobes, uprobes, tracepoints).
- **BTF Engine**: Parses type metadata embedded within ELF sections (`.BTF`) to dynamically adjust BPF bytecode offsets at runtime against target kernel structures.

### Directory & Component Map
```text
libbpf/
├── src/
│   ├── bpf.c          # Low-level wrappers around the bpf() system call
│   ├── libbpf.c       # Core ELF loader, object lifecycle, and CO-RE relocation engine
│   ├── btf.c          # BTF parsing, encoding, and type-matching logic
│   ├── libbpf_internal.h # Internal data structures and error-handling macros
│   └── Makefile       # Build logic for libbpf.a and libbpf.so
├── include/
│   ├── asm/barrier.h  # Low-level memory barriers and atomic acquisition primitives
│   ├── linux/compiler.h # Compiler abstractions (likely, unlikely, READ_ONCE, WRITE_ONCE)
│   ├── linux/err.h    # Pointer error-encoding macros (ERR_PTR, PTR_ERR, IS_ERR)
│   └── uapi/linux/bpf.h # User-space API definitions for BPF commands and structures
```

### Lifecycle & Execution Flow
1. **Compilation Phase**: Clang compiles source C code into an ELF object file containing BPF bytecode, map definitions, and `.BTF` type metadata.
2. **Object Initialization**: User-space application invokes `bpf_object__open()` or `bpf_object__open_file()` to parse the ELF structure into memory without interacting with the kernel.
3. **CO-RE Relocation & Verification**: `libbpf` inspects local BTF metadata, queries the running kernel's BTF (`/sys/kernel/btf/vmlinux`), and patches instruction offsets for field accessors (`bpf_core_read`).
4. **Map Creation**: `libbpf` iterates through map definitions and executes `bpf(BPF_MAP_CREATE, ...)` syscalls to allocate maps within kernel memory, storing file descriptors.
5. **Program Loading**: Verifier bytecode verification is triggered via `bpf(BPF_PROG_LOAD, ...)`. The kernel's internal verifier analyzes safety constraints.
6. **Attachment & Execution**: Program file descriptors are attached to specific hooks (e.g., netdev, tracepoint, kprobe) using specialized attach functions or raw `perf_event_open` setups.

## 2. Core Mechanisms, Algorithms & Low-Level Techniques

### Fundamental Invariants
- **Memory Consistency & Ordering**: Relies on strict multi-core barriers and memory models defined in `include/linux/compiler.h`. Synchronization primitives use Acquire-Release semantics (`smp_store_release`, `smp_load_acquire`) and explicit CPU barriers (`smp_mb`, `smp_rmb`, `smp_wmb`) across architectures (`x86_64`, `aarch64`).
- **Error Propagation**: Kernel and system call errors are encoded directly into pointer values utilizing standard Linux kernel patterns:
  $$\text{MAX\_ERRNO} = 4095$$
  Pointers within the range `[0xfffffffffffff000, 0xffffffffffffffff]` designate negative error codes. Handled via `IS_ERR()`, `PTR_ERR()`, and `ERR_PTR()`.
- **CO-RE (Compile Once – Run Everywhere)**: Instead of recompiling BPF code for every target kernel version, `libbpf` captures access targets via relocation records. At load time, it calculates field offsets dynamically based on the running kernel's actual memory layout.

### Subsystem Interfacing
- **Syscall Multiplexing**: The `bpf()` system call command enum (`bpf_cmd`) handles all core interactions:
  - `BPF_MAP_CREATE`, `BPF_MAP_LOOKUP_ELEM`, `BPF_MAP_UPDATE_ELEM`, `BPF_MAP_DELETE_ELEM`
  - `BPF_PROG_LOAD`
  - `BPF_OBJ_PIN`, `BPF_OBJ_GET`
  - `BPF_PROG_ATTACH`, `BPF_PROG_DETACH`

### Security & Integrity Model
- **Privilege Separation**: Requires `CAP_SYS_ADMIN` or `CAP_BPF` capabilities to load unprivileged/privileged BPF programs into the kernel ring.
- **Verifier Enforcement**: In-kernel verifier guarantees memory safety, bounded loops, and null-pointer checks before allowing bytecode execution.

## 3. Data Contracts, Structs & Core API Signatures

### Compiler & Barrier Primitives (`include/linux/compiler.h`)
```c
#define likely(x)       __builtin_expect(!!(x), 1)
#define unlikely(x)     __builtin_expect(!!(x), 0)

#define READ_ONCE(x)    (*(volatile typeof(x) *)&x)
#define WRITE_ONCE(x, v) (*(volatile typeof(x) *)&x) = (v)

#define barrier()       asm volatile("" ::: "memory")
```

### Error Handling Contracts (`include/linux/err.h`)
```c
#define MAX_ERRNO       4095
#define IS_ERR_VALUE(x) ((x) >= (unsigned long)-MAX_ERRNO)

static inline void *ERR_PTR(long error_)
{
    return (void *)error_;
}

static inline long PTR_ERR(const void *ptr)
{
    return (long)ptr;
}

static inline bool IS_ERR(const void *ptr)
{
    return IS_ERR_VALUE((unsigned long)ptr);
}

static inline long PTR_ERR_OR_ZERO(const void *ptr)
{
    return IS_ERR(ptr) ? PTR_ERR(ptr) : 0;
}
```

### Low-Level BPF Syscall Wrapper Signature (`src/bpf.c` concept)
```c
int bpf(enum bpf_cmd cmd, union bpf_attr *attr, unsigned int size);
```

## 4. Production-Ready Scaffolding Boilerplate (Copy-Paste)

Below is a complete, compilable C program demonstrating how a low-level user-space application initializes, loads, and manages an ELF-based BPF object using `libbpf` primitives and error handling patterns derived from the source tree.

```c
/* SPDX-License-Identifier: (LGPL-2.1 OR BSD-2-Clause) */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <bpf/libbpf.h>
#include <bpf/bpf.h>
#include "linux/err.h"

static int libbpf_print_fn(enum libbpf_print_level level, const char *format, va_list args)
{
    if (level > LIBBPF_INFO)
        return 0;
    return vfprintf(stderr, format, args);
}

int main(int argc, char **argv)
{
    struct bpf_object *obj = NULL;
    int err;

    // Set up libbpf debug output callback
    libbpf_set_print(libbpf_print_fn);

    // Verify user requirements (e.g., file existence)
    const char *bpf_file = "my_bpf_program.bpf.o";
    if (access(bpf_file, R_OK) != 0) {
        fprintf(stderr, "ERROR: Target BPF object %s not accessible: %s\n", 
                bpf_file, strerror(errno));
        return 1;
    }

    // Open BPF application ELF file
    obj = bpf_object__open(bpf_file);
    if (IS_ERR_OR_NULL(obj)) {
        err = PTR_ERR_OR_ZERO(obj);
        fprintf(stderr, "FAILED to open BPF object: %d\n", err);
        return 1;
    }

    // Load BPF object into kernel
    err = bpf_object__load(obj);
    if (err) {
        fprintf(stderr, "FAILED to load BPF object into kernel: %s\n", strerror(-err));
        bpf_object__close(obj);
        return 1;
    }

    printf("SUCCESS: BPF object loaded and verified successfully.\n");

    // Clean teardown
    bpf_object__close(obj);
    return 0;
}
```

### Compilation Command
```bash
gcc -O2 -Wall main.c -lbpf -lelf -o bpf_loader
```

## 5. Engineering Invariants, Tradeoffs & Gotchas

### Performance & Concurrency Characteristics
- **Zero-Copy Ring Buffers**: High-throughput event streaming relies on shared-memory ring buffers (`struct bpf_ringbuf`), eliminating memory copy overhead between kernel space and user space.
- **Lockless Map Lookups**: BPF maps leverage RCU (Read-Copy Update) and per-CPU variations to allow lock-free insertions and lookups from high-frequency interrupt contexts.

### Failure Modes & Edge Cases
- **Kernel Version Mismatches**: Non-CO-RE legacy applications will fail to load if a struct layout changes between the compilation target and the running kernel. Always prefer BTF-powered CO-RE (`bpf_core_read`).
- **Verifier Rejection Loops**: Complex logic bounds or un-bounded loops will trigger strict BPF verifier rejection (`EINVAL`), crashing program load attempts. Ensure all loops are bounded by compile-time constants or simple conditional checks recognizable by the verifier.

### Hard Prerequisites
- **Libraries**: `libelf` must be installed (`libelf-dev` or `elfutils-libelf-devel`).
- **Kernel Config**: Linux Kernel $\ge 5.0$ recommended with BTF generation enabled (`CONFIG_DEBUG_INFO_BTF=y`).
